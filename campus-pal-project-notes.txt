Campus Pal – Product and UX Expansion Notes

Repository: Nyxsteria/campus-pal

Overview
- Campus Pal is currently a static front-end prototype/demo for a UK college social network.
- The app currently includes a campus feed, stories, social cards, menu, people discovery, and accessibility-minded visual design.
- The goal is to evolve it into a full polished campus social experience with real users, a real college selection flow, a complete frontend UX, and a realistic API/backend architecture.

Current status
- Public repo, not archived, active in a lightweight demo sense.
- No open issues or PRs.
- README confirms this is a prototype, not a production system.
- User, college, authentication, messaging, real data, notifications, and friend connections are not implemented yet.

Vision
Build a polished campus-first social platform that feels like a modern, safe, and welcoming student community network, similar in spirit to a UK college social app, but with stronger privacy, accessibility, and user trust.

Core user experience goals
- Real user experience from first visit to ongoing daily campus life
- Real college selection and onboarding
- Full profile setup with pronouns, course, year group, and privacy settings
- Campus social feed with relevant posts, clubs, notices, events, and recommendations
- Real friendship and messaging flows
- Fully accessible UI in both light and dark mode
- Clear keyboard, screen reader, and motion support
- Clean and modern UK-campus aesthetic

Planned user flow
1. Welcome / sign in
2. Select college or campus
3. Create profile
4. Choose privacy and accessibility preferences
5. Explore home feed
6. View campus stories and notices
7. Join clubs and societies
8. Connect with classmates and friends
9. View or send messages
10. Check dining information
11. Manage profile and settings

Backend architecture recommendations
- Use a modern backend stack such as Next.js + Postgres + Prisma, or Node/NestJS + Postgres.
- Store user, college, posts, media, clubs, events, messaging, and settings in a relational database.
- Use an authentication service with secure session tokens or JWT-based auth.
- Separate API layers for feed, social interactions, messaging, and notifications.
- Add real-time layer for messages and incoming notifications.
- Add upload service for profile photos and post media.
- Add analytics and moderation service for abuse prevention and community safety.

Accessibility and UI design standards
- Keyboard navigation on all interactive elements
- Visible focus states on buttons, links, inputs, and dialog controls
- Adequate contrast across all themes
- Respect prefers-color-scheme and user theme selection
- Support reduced motion and prefers-reduced-transparency
- Use semantic landmarks: header, nav, main, section, aside, footer, dialog
- Add aria-labels for icon-only buttons and navigation actions
- Use live regions for toast notifications and action confirmations
- Ensure modals and dialogs have accessible titles and keyboard close behavior
- Support screen reader descriptions for important campus updates and feed actions
- Keep interactive targets large enough for mobile and tablet use

Theme direction
Light mode
- Background: off-white or soft neutral
- Surface: white or pale grey
- Text: dark slate
- Accent: purple / lavender
- Borders: soft grey
- Good readability and airy spacing

Dark mode
- Background: near-black / deep charcoal
- Surface: darker grey
- Text: off-white
- Accent: purple / lilac
- Borders: subtle cool grey
- Preserve clarity and accessible contrast

Current prototype notes
The existing prototype is visually strong and includes an accessible foundation, but it is intentionally a static demo. It should be treated as the starting design language rather than the final product. The next implementation should expand its aesthetic while turning it into a real student social platform with actual back-end data and interaction flows.

Next practical step
- Reuse the existing design language and UI patterns
- Build a realistic data-driven frontend around those screens
- Then add the backend/API layer needed for real users, college selection, messaging, feed, clubs, and dining
- Final step: implement strongest accessibility and theme controls for light and dark mode

This file is intended to capture the current direction so the work can continue later without losing the product vision.
